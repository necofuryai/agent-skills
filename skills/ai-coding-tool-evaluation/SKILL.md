# AIコーディングツール評価

ツール名の序列ではなく、対象作業を最後まで実行できる経路と費用から選択肢を決める。

## 1. 判断条件を固定する

- 比較対象、主な作業、必要なアプリ・アカウント・クラウド、月間利用頻度、予算、個人利用か組織利用かを特定する。
- 現在契約中のプランと追加契約の候補を分ける。年額契約や購入を前提に置かず、判断期間を確認する。
- 比較を左右する不足情報だけを質問し、それ以外は明示した仮定で進める。

比較対象と作業シナリオが一対一で対応したら、根拠を集める。

## 2. 現在の根拠を集める

料金、利用枠、モデル、製品機能、データ利用、保持、管理機能は変動情報として扱い、回答時点の公式一次情報を確認する。画面やローカル設定を確認した場合は、次の区分を保つ。

- 公式に公開された製品・契約の事実
- 現在の端末またはアカウントで観測した状態
- その事実から導く推論
- 確認できない条件

古い料金表、マーケティング上の倍率、異なる製品間のtoken量をそのまま換算しない。通貨換算を示す場合は、換算日とレートを併記する。

各候補について、判断を変える現在情報と未確認事項が揃ったら比較へ進む。

## 3. 作業シナリオで比較する

必要な項目だけを使い、候補ごとに同じ条件で比較する。

- ローカルrepository、terminal、worktreeでの実行経路
- 認証済みbrowser、native app、desktop contextへの到達性
- GitHub、CI、cloud、observabilityから原因へ結びつける手段
- 利用可能なmodel、provider選択、contextと並列作業
- 承認、権限、secret、外部providerへのデータ送信境界
- 月額、含まれる利用枠、超過課金、速度制限、管理機能
- setup、再現性、既存workflowとの切替コスト

モデル単体の印象より、再現、根拠取得、変更、検証までの経路を優先する。

## 4. 条件付きで推薦する

- 主用途に対する既定候補を一つ示し、代替候補と見送り理由を続ける。
- 推薦が逆転する利用頻度、必要な画面・権限、料金、プライバシー条件を明記する。
- 不確かな利用量では月契約または現在契約内の試行を既定とし、観測期間と見直し条件を置く。
- 購入、install、login、設定変更、外部providerへの送信は、ユーザーがその操作を明示した場合だけ実行する。

完了時は、確認日、使用した公式情報と観測状態、比較表または同等の対応関係、推薦、逆転条件、未確認事項を返す。
